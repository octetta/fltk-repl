# Agent Notes

## macOS Application Bundle & Release Fixes (August 2026)

**Issue Encountered:**
The macOS `.app` bundle generated by the `one-click-release.yml` GitHub Action was failing to open on modern macOS (e.g., Sequoia on Apple Silicon) with a generic prohibitory icon or returning `-10825` (`kLSIncompatibleSystemVersionErr`) when launched via `open` in the terminal.

**Root Causes & Fixes Applied:**

1. **Architecture Missing (Universal Binary):**
   * **Problem:** `macos-latest` runner builds on ARM64 by default, producing an ARM64-only binary that would fail on Intel Macs.
   * **Fix:** Added `-DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"` in `.github/workflows/one-click-release.yml` to compile a true Universal Binary.

2. **CFBundleExecutable Mismatch:**
   * **Problem:** The `OUTPUT_NAME` for the CMake target was set to `skrepl`, but the generated `Info.plist` retained the target's internal name (`skred_repl`) as the executable. LaunchServices viewed this as a corrupted bundle.
   * **Fix:** Hardcoded `<string>skrepl</string>` for the `CFBundleExecutable` key in `cmake/Info.plist.in`.

3. **LaunchServices Version Alignment (-10825):**
   * **Problem:** `Info.plist` declared `LSMinimumSystemVersion` as `11.0`, but because the CI runner was macOS 14 without an explicit deployment target, the Mach-O binary's internal `LC_BUILD_VERSION` was set to require `14.0`. LaunchServices detected the discrepancy between the `Info.plist` and the binary and rejected the app with a `-10825` Incompatible System Version error.
   * **Fix:** Added `-DCMAKE_OSX_DEPLOYMENT_TARGET=11.0` in `.github/workflows/one-click-release.yml` so the binary's deployment target perfectly matches the `Info.plist` requirements.

**Testing Note:**
LaunchServices caches `.app` bundles heavily. If testing locally, rename the `.app` folder (e.g., `skrepl-test.app`) or run `lsregister -f` to force macOS to re-read the `Info.plist`.
